# X 图片收藏

Chrome / Edge 116+ 扩展。在 X 帖子操作栏增加「↓ + 媒体数量」按钮，一键保存本帖原图和视频，按作者的 **@用户名** 归档，并使用 **SHA-256 内容去重**。

## 安装与更新

1. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
2. 打开「开发者模式」，点击「加载未打包的扩展程序」（部分版本称「加载已解压的扩展程序」）。
3. 选择本仓库中的 `x-media-saver` 目录（包含 `manifest.json`），或将 `dist/x-image-saver.zip` 解压后选择解压目录。
4. 打开或刷新 <https://x.com>。

无需安装依赖或编译。开发时直接加载 `x-media-saver` 目录；修改后在扩展管理页重新加载扩展，再刷新 X，无需重新安装。升级新增视频权限时，Chrome 可能要求重新启用扩展。

需要把源码同步到固定的本地安装目录时，可运行以下命令，再在浏览器中重新加载扩展并刷新 X。安装目录须与源码目录分开；同步只复制扩展打包内容，不会修改浏览器中的下载记录或设置。

```sh
python3 scripts/sync-installed.py /path/to/local-install
```

## 保存目录

- 图片：`下载目录/作者用户名/图片/发布时间_帖子ID_序号.jpg`（保留原图片格式）。
- 视频：`下载目录/作者用户名/视频/发布时间_帖子ID_序号.mp4`。
- 发布时间采用北京时间（固定 UTC+8），格式为 `YYYY-MM-DD_HH-mm-ss`，例如 `2024-09-28_20-06-00_1840000000000000000_1.jpg`。按文件名排序即可按发帖时间排列，单帖保存和批量下载使用同一规则。
- 时间直接从 X 的帖子 ID 解析，不增加网络请求；无法解析时间的早期或异常 ID 保留 `帖子ID_序号` 文件名。新规则只影响之后实际保存的文件，已有文件不会自动改名，已有去重记录继续有效。浏览器扩展无法把系统的「添加日期」或文件创建时间改为发帖时间。
- 扩展菜单可设置外层目录，例如 `X收藏`，之后保存到 `下载目录/X收藏/作者用户名/图片/` 和 `视频/`。
- 「用户 ID」指可读的 **@用户名**，不是 X 内部的数字账号 ID。用户名更改后，后续文件会进入新目录。

扩展只能在浏览器的默认下载目录下创建子目录。要保存到其他磁盘，请先修改浏览器下载位置；关闭浏览器的「下载前询问每个文件的保存位置」可获得一键保存体验。

## 图片与视频

- 图片请求 X 的 `name=orig` 原始尺寸，实际质量和可用性由 X 决定。
- 视频从 X 已加载的帖子数据里选取码率最高的 MP4，也支持以 MP4 播放的动图。
- 支持时间线、用户主页、帖子详情和滚动加载。普通转发按原作者归档；引用帖只保存外层作者自己的媒体。要保存引用的媒体，请打开原帖。
- 不保存头像、表情、链接卡片或视频封面。敏感内容需先点开，媒体加载后按钮才会出现。
- 直播、仅有 HLS 播放列表或不提供 MP4 的视频暂不支持。视频元数据未加载时，可播放一下视频或刷新页面再试。
- 下载中禁止重复点击。浏览器确认保存完成后显示绿色对勾，提示分别显示新增、跳过、失败数量；失败可重试，只补存未保存的文件。

## 按作者批量下载图片

打开作者主页，点击右下角的「下载此作者图片」。扩展会进入该作者媒体页的图片筛选（`/用户名/media?filter=photo`），自动滚动收集并逐帖保存原图；多图帖子使用页面接口数据中的完整图片列表，视频封面不会当作图片下载。仅收集该作者自己发布的图片，不保存其他作者的转发、引用图片或视频；当前功能不包含视频批量下载。

下载期间请保持该页打开。面板同时显示本次处理的帖子数、发现的图片数，以及保存、跳过和失败的图片数；多图帖只计一帖，快速定位切换为下载后沿用累计帖子数。另显示当前作者、当前图片目录的「历史已存：N 帖 · M 张」，按插件已确认成功的记录统计；同一文件的重复记录合并，历史帖数按已保存文件的帖子 ID 统计。历史数字会在新文件保存成功后更新，删除文件或清空浏览器下载列表不会清除这些成功记录。

可点击「停止」；当前帖已经开始的下载会继续完成，之后不再开始新帖。切换作者或离开媒体页也会停止任务。在作者媒体页的图片筛选中启动任务时，从当前滚动位置向下收集，不刷新页面，也不跳回页首。停止后点击「从当前位置继续补存」即可接着收集，并沿用现有去重记录补存未成功保存的图片；页面已收集到的图片数据也会继续用于补存。需要从头收集时，先手动回到页首再开始。

面板以黄色边框标记当前处理的可见图片，显示对应帖子和下载到第几张；媒体网格未单独显示多图帖中的某张图片时，标记该帖的代表缩略图。切换处理图片时，已加载但位于视野外的对应缩略图会自动滚到视野中，避开顶部导航；同一张图片的进度轮询不会反复拉回手动滚动的位置。边框随滚动更新，不影响页面点击；停止后保留当前位置。快速模式按批次跟随到最新判断的位置，不增加逐图查询。

等待 X 加载时显示无进展计时；连续 90 秒没有滚动或新图片进展时停止，并提示无法确认全部历史已加载。失败原因持续显示在面板中，包括具体文件、HTTP 状态、网络断开、浏览器中断、磁盘空间不足等。图片接口返回限流或拒绝访问时停止任务，稍后可从当前位置继续；个别图片失败会保留原因并继续后面的图片。此功能保存的是 X 当前向登录用户开放的图片；受保护、已删除、未返回的历史内容和限流可能造成不完整，不能保证备份账号全部历史。

已保存过很多图片、想快速找到接着下载的位置时，使用独立的「快速定位并补存」按钮。可以先手动滚到大致位置，再点击按钮：它以点击时第一排可见图片为起点，沿 X 图片时间线向更早的帖子定位，上方已缓存的较新帖子不会把任务拉回去；停止后可以手动换个位置再定位，切换为正常下载后也沿用这次起点。当前没有已加载图片且页面已经向下滚动时，会提示等待或稍微向上滚动，不会退回检查旧缓存。每批最多 100 条帖子、一次读取当前保存目录的已完成记录，在内存中批量比较后越过已确认保存的图片，不逐帖创建下载任务，也不读取原图或计算哈希。遇到没有确认记录的图片（包括部分保存、失败或历史记录缺失）时，自动切换为正常下载，刚刚确认保存的图片不会再逐帖检查；发现和跳过数量沿用快速阶段的累计值，衔接处的图片不会重复计数。正常下载仍保留 URL 和 SHA-256 去重。快速模式仍需等待 X 逐页加载，无法直接跳到尚未加载的历史位置，也不会绕过限流；连续 90 秒无进展会停止，不能据此保证全部历史已保存。修改保存目录后需重新定位。

## 按内容去重

去重范围是**同一作者的同一媒体目录**：不同作者、不同外层保存目录仍分别归档。

1. 已保存过的媒体地址先查本地记录。曾成功保存就直接跳过，无需再次读取内容；删除源文件、清空浏览器下载列表后仍会跳过。
2. 新地址完整读取后，以流式 SHA-256 计算指纹。即使帖子 ID、文件名、链接不同，文件内容完全相同也只保留一份。
3. 新内容通过 Blob 直接交给浏览器保存，复用已读取的数据，不再请求一次原文件。视频分块计算哈希，不在 JavaScript 中创建整个视频的 ArrayBuffer。
4. **按住 Shift 点击保存按钮可强制重新下载**，绕过已有记录；同一帖内内容完全相同的媒体仍只存一份。普通点击只补存未成功下载的文件，失败可直接重试。多个标签页普通点击保存同一文件会合并任务。
5. 成功记录包含媒体地址、内容指纹、保存路径及完成时间，保存在扩展的本地存储中；刷新页面后按钮会恢复已下载状态。

哈希比较的是**完全相同的文件字节**。重新压缩、转码或改动过的媒体即使看起来相同，也算不同文件。新链接仍需完整传输一次才能识别；去重主要节省磁盘空间。

扩展只校验自己保存过的记录，不能任意扫描磁盘或读取你手动存放的文件。卸载扩展或清除扩展数据会丢失记录；清空浏览器下载列表不会清除扩展内已确认成功的记录。旧版下载记录可按原图地址识别并跳过，历史文件不会自动移动到新子目录；跨链接的内容哈希去重适用于新版建立的记录。升级前未建立成功标记的旧记录需借助浏览器下载列表迁移；若该列表已清空，则无法恢复这部分旧记录。

## 权限与隐私

- `downloads`：保存文件、查询是否完成。
- `storage`：在本机保存目录设置、媒体哈希、下载编号及成功记录。
- `offscreen`：在隐藏的扩展页面中计算哈希、创建可复用的 Blob 下载源。
- X / Twitter 内容脚本：识别已加载帖子、插入按钮，提取视频元数据。
- `pbs.twimg.com`、`video.twimg.com`：读取 X 图片和视频。

不需要 X API 密钥，不读取 Cookie，不上传媒体、浏览记录或账号信息，无远程脚本和统计分析。页面桥接只从 X 已加载的时间线 / 帖子响应中提取视频地址，不另行调用账号 API。

SHA-256 使用随扩展附带的 MIT 开源库 `@noble/hashes`。版本、来源和校验值见 `vendor/noble-hashes/README.md`，运行时不下载代码。X 页面或数据结构变动后，可能需要调整选择器或视频解析逻辑。

## 开发与验证

以下命令均在 `x-media-saver` 目录中执行，需要 Node.js 20+ 和 Python 3，无需运行 `npm install`。

```sh
npm test
npm run check
npm run pack
```

自动测试覆盖原图 / 视频 URL、视频清晰度选择、作者批量收集与停止、快速定位的批量历史查询与未保存边界、多图元数据、分类归档、SHA-256 标准向量、重复内容、并发点击、删除后仍跳过与强制补存、失败补存和消息来源校验。打包产物为 `dist/x-image-saver.zip`。

浏览器模拟页 `tests/fixture.html` 使用模拟扩展 API，不会下载真实文件。安装 `agent-browser` 后，可在 `x-media-saver` 目录启动 `python3 -m http.server 8765 --bind 127.0.0.1`，另开终端运行：

```sh
agent-browser --session x-image-saver open http://127.0.0.1:8765/tests/fixture.html
agent-browser --session x-image-saver eval --stdin < tests/browser-check.js
agent-browser --session x-image-saver eval --stdin < tests/author-browser-check.js
agent-browser --session x-image-saver close
```

每次检查前重新打开模拟页面；检查会修改测试帖子的 DOM。模拟页不能保证 X 后续改版的兼容性。

`tests/native-check.mjs` 还会在隔离 Chrome 中加载真实扩展，使用受控网络响应验证内容脚本、最高码率视频选择、离屏哈希、原生下载、磁盘文件完整性与删除后仍跳过与强制补存。需要本机有 `agent-browser`、`ffmpeg` 和 Node 20+：

```sh
agent-browser --session xis-v12 --args '--enable-unsafe-extension-debugging' open about:blank
node --experimental-websocket tests/native-check.mjs xis-v12
agent-browser --session xis-v12 close
```

原生检查仅用于隔离测试浏览器，生成的短视频和下载文件均放在被 Git 忽略的 `test-results/` 中。重新运行前关闭该隔离浏览器以清空其扩展状态。

GitHub Actions 会自动运行语法检查、单元测试和打包校验，成功后提供 `x-media-saver` ZIP 构建产物；完整浏览器验证仍按上述方法在本机执行。
